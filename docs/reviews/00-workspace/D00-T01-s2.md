## adversarial: needs-attention

1. **External CSS references bypass the regex.** `scripts/check-image-asset.py:124`  
   CSS escapes are not decoded before checking URLs or imports. Insert either of these into an otherwise valid SVG:
   ```xml
   <style>rect { fill: u\72l(https://example.invalid/a.svg#p) }</style>
   <style>@impor\74 "https://example.invalid/a.css";</style>
   ```
   Both pass the checker, but CSS tokenization recognizes `url` and `@import`. The prohibition needs to operate on parsed tokens or reject unsupported CSS syntax. [CSS Syntax specification](https://www.w3.org/TR/css-syntax-3/)

2. **External XML stylesheets are ignored.** `scripts/check-image-asset.py:94`  
   Prepend `<?xml-stylesheet type="text/css" href="https://example.invalid/a.css"?>` to the clean SVG fixture. ElementTree discards the processing instruction, so the checker returns success despite the external stylesheet reference. Inspect or reject processing instructions before they disappear during parsing.

## consistency: needs-attention

3. **Invalid repeated size arguments produce inconsistent exit codes.** `scripts/check-image-asset.py:213`  
   For a valid 4×4 PNG, `--size 4x4 --size 8x8` exits **1**, while adding `--format png` makes the same invalid argument combination exit **2**. The documented contract assigns invalid arguments exit 2. Validate the combination consistently after detecting the format.

   Comparison with the sibling checker remains unverified because local reads were unavailable.

## source-defect: needs-attention

4. **CRC validation does not establish PNG validity.** `scripts/check-image-asset.py:70`  
   Using the test helpers, construct:
   ```python
   ia.PNG_SIGNATURE + chunk(
       b"IHDR", struct.pack(">IIBBBBB", 1280, 640, 8, 0, 0, 0, 0)
   ) + chunk(b"IEND", b"")
   ```
   This has no image data but passes `--size 1280x640`. Adding `chunk(b"IDAT", b"not zlib")` also passes because its CRC is valid. Invalid IHDR methods and bit-depth combinations likewise go unchecked. Consequently, the downstream build can accept unusable PNG outputs, including PNG payloads inside ICOs. Validate required chunk structure and bounded decompression of image data. [PNG specification](https://www.w3.org/TR/png-3/)

5. **Twelve bytes are accepted as a complete ICO bitmap.** `scripts/check-image-asset.py:148`  
   Construct `ico((32, 32, struct.pack("<Iii", 40, 32, 64)))` with the supplied helper. It passes `--size 32x32`, although even the claimed 40-byte bitmap header is truncated and no pixels exist. Validate the full supported DIB header and required pixel/mask storage before accepting the dimensions.

6. **Non-finite SVG coordinates and dimensions pass.** `scripts/check-image-asset.py:103`  
   Replace the clean fixture’s viewBox with `viewBox="nan 0 48 48"` and run with `--size 48x48`: it passes. `viewBox="0 0 nan inf"` passes without a requested size. Python accepts these floats, and comparison with zero does not reject NaN. Require all four values to be finite and valid SVG numbers.

7. **Valid SVG roots can fail format detection.** `scripts/check-image-asset.py:44`  
   `<s:svg xmlns:s="http://www.w3.org/2000/svg" viewBox="0 0 48 48"/>` is rejected as an unknown format, although `svg_check()` accepts that expanded root name. UTF-16 SVG documents also fail the byte heuristic. Detect SVG through XML parsing and its expanded root name, rather than requiring a literal `<svg` near the beginning.

## Dispositions of round 1

All nine findings were real and are fixed in the commit after 13b9ff5, each with a test that fails on 13b9ff5 (18 failing cases there, 19 tests passing after).

1. CSS escapes: any backslash in a style element or attribute value is refused (`CSS escape`), so no escape can spell `url` or `@import`.
2. `<?xml-stylesheet?>`: every processing instruction other than the XML declaration is refused before parsing drops it.
3. Exit codes: more than one `--size` for a PNG or SVG exits 2 with or without `--format`.
4. PNG validity: IHDR fields are validated (depth and colour type pairs, methods), IDAT must exist and be consecutive, a palette image needs PLTE, and the data must inflate, streamed and counted, to exactly the byte count its dimensions need (Adam7 included).
5. ICO bitmaps: `bmp_size` needs a full header, one plane, 1/4/8/24/32 bits, no compression, and every palette, pixel and mask byte.
6. viewBox: four finite numbers with positive width and height.
7. Detection: an SVG is detected from its root element's expanded name (any prefix), in UTF-8 or UTF-16.
8. The ICO fixture now carries complete 32-bit and 8-bit bitmaps; truncation is tested separately.
9. The zero-size rules each have a refusal test; mutating them, the data length check or the CSS escape check fails the suite.

All 927 committed SVG, PNG and ICO assets still pass.
