## Fix

`plainScalarProblem` refuses a plain scalar that opens with a reserved indicator (`-`, `?` and `:` only when a space follows), holds `: ` or ends with `:`; the top-level reader and the `hooks:` block reader (for a key's value) both apply it, with an error telling the writer to quote the value. After the fix the verifier and both loaders agree on all 26 probed lines, and the five agents in `.claude/agents/` still pass.

Tests: `scripts/tests/test_verify_agent_tiers.py` runs `node scripts/verify-agent-tiers.mjs` on fixture agent directories. Ran 6 tests, OK; on the previous verifier 13 subtests fail, one per refused case.

## Dispositions after round 1

All seven findings were verified against both loaders. They are fixed by narrowing the accepted language until every accepted line is valid YAML, not by patching each case:

1. P1 a quoted key's value could carry a second key: fixed. The `hooks:` reader takes at most one key per line (`holds a second key on one line`).
2. P1 a tab after a sequence dash: fixed. A tab anywhere in a `hooks:` line is refused.
3. P2 JavaScript `trim()` removed a non-breaking space that YAML keeps as content: fixed. Only spaces and tabs are trimmed, so `description: hello:` followed by a non-breaking space passes, as both loaders accept it.
4. P1 `description: "a"b"` passed: fixed. Quoted scalars may not hold their own delimiter (a single quote only doubled), and text after the closing quote is refused.
5. P1 a backslash escape in a `hooks:` double-quoted value: fixed, refused as at the top level.
6. P1 `|++` in `hooks:`: fixed. Block scalars are refused inside `hooks:` (a hook command fits on one line, quoted if needed).
7. P1 inconsistent block scalar indentation: fixed in `hooks:` (no block scalars) and at the top level, where a later line indented less than the first content line, or with a tab, is refused.
