# Review: D02 T01 §3 UI Automation Capture Tool

## Self-review

Failure modes: acting on the operator's own windows (typing into their work, changing their settings), leaving a menu open or a process behind, recording positions under the wrong display or scaling, copying Microsoft's ScreenTip prose, recording add-ins as Office, an `idMso` guessed rather than known, and losing hand-written annotations on a re-capture.

Verified so far:

- Safety: Word runs as the tool's own `DispatchEx` instance; an app that allows one instance only is launched only when not running; Outlook is never started. The operator's Word (pid 70908, open since 2026-10-16) was running through every live run and was never touched; after each run only pid 70908 remained.
- Profile: the tool places its window on the display that is 1920 by 1080 at 96 DPI (the second display, read by a DPI-aware process), maximises it, and checks display, DPI, maximised, display language, ribbon shown and theme (by the title bar's colour). The Home capture recorded bounds under `fhd-100`.
- Facts only: labels are UI Automation names; `idMso` is set only when the app's baseline lists the candidate (own id, then the drop-down part's id, then a part's id), which put Find on `SelectMenuExcel`, the split button the baseline lists in Word's Editing group; KeyTips come from the access key path with no key pressed; help text and full description are never read (`test_screentip_text_is_never_read`).
- Add-ins: the Adobe Acrobat group on Home (no control the baseline knows) and the Acrobat tab (no identifier) are skipped and listed.
- Live checkpoint: `capture-ui.py --app word --tab Home --out R:\scratch\word-home.json` exit 0 (55 records, bounds under fhd-100); `check-inventory.py R:\scratch\word-home.json` exit 0; Paste is `splitButton` (`PasteMenu`), Styles is `gallery` (`QuickStylesGallery`), Bold is `toggleButton` with KeyTip `1`.
- Menus: two live runs of `--all-tabs --expand` stopped safely (exit 1, nothing written, instance quit) when a popup did not report closed. Probes showed the cause: Word's expand state is unreliable both ways (Underline reports collapsed while open; Show Comments reports expanded while closed), and menu items live in a Menu element under the app window. Closing is now judged by the popup and menu being gone, with expand-then-collapse for drop-downs that ignore Collapse.
- Full run: `--all-tabs --expand` exit 0, 1471 records (9 tabs, 54 groups, 215 controls, 1193 menu and gallery items), bounds under fhd-100, Acrobat and OneNote add-in groups and the Acrobat tab skipped; `check-inventory.py` exit 0. A first full run had captured no items: Word puts an empty Menu shell before the menus that hold them, so every open Menu is read now (test covers the shell).
- Labels: Word embeds an unseen level placeholder (U+0001) in six numbering gallery names; the tool drops control characters and the schema now refuses them in every string field (`noControl`, `test_a_control_character_in_any_string_is_refused`, which flags the earlier capture). Visible characters Word shows (ellipsis, pilcrow, degree sign, non-breaking hyphen) stay. Paste's menu lists what the clipboard allows at capture time (3 items with an empty clipboard).
- Merge: an annotated `behaviour` survived a `--merge` re-capture while `bounds` refreshed.
