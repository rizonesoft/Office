## Self-review

Verified so far:

- Live checkpoint: `capture-ui.py --app word --tab Home --out R:\scratch\word-home.json` exit 0 (55 records, bounds under fhd-100); `check-inventory.py R:\scratch\word-home.json` exit 0; Paste is `splitButton` (`PasteMenu`), Styles is `gallery` (`QuickStylesGallery`), Bold is `toggleButton` with KeyTip `1`.

- Plan corrections (dated in the TODO): the blank document is created inside the tool's own instance rather than from a fixture; KeyTips come from the access key; `--layout simplified` exits 2 on a build without the switch, and switching moves to §15; contextual tab triggering moves to §5 with its fixture.

## adversarial: needs-attention

1. **[P1] Single-instance launch can attach to and close the operator’s application.** `scripts/capture-ui.py:414` checks running processes before `Dispatch`, but does not establish ownership afterward. If PowerPoint starts between those operations, `Dispatch` can return that instance. The tool creates a presentation before validating its process; when validation fails, `close()` marks **every** presentation saved and closes it (`:460`). Reproduce by making `running()` return false and the injected dispatcher return an existing application containing an unsaved presentation. Ownership must be established before creating documents, and cleanup must not close unowned documents.

2. **[P1] Publication is not atomic across process termination.** `scripts/lib/office_com.py:115` renames the existing destination away before installing its replacement at `:116`. Terminating the process between those calls leaves the destination missing; exception rollback cannot run after process termination. Reproduce by terminating immediately after the first rename during `--merge`. The test at `scripts/tests/test_capture_ui.py:236` interrupts staging with a catchable exception, so it does not exercise this failure. The capture’s single-file publication should atomically replace the existing destination.

## consistency: needs-attention

3. **[P2] Duplicate labels can transfer annotations to the wrong control.** `scripts/capture-ui.py:77` assigns identity from label and encounter order, while `:188` merges solely by that identity. Reproduce with two same-label controls having distinct automation IDs, annotate the first, then reverse their traversal order. The annotation remains on the first generated ID but now describes the other control. Capture identity needs a stable discriminator before merge can safely preserve annotations.

4. **[P2] Missing baseline identifiers are treated as proof of add-in ownership.** `scripts/capture-ui.py:145` and `:156` discard unidentified tabs and groups whose controls are absent from the baseline. A built-in control introduced after the baseline, or exposed without a recognized identifier, satisfies the same condition. Reproduce with a built-in group containing one unknown-ID control: the entire group disappears and is reported as an add-in. Unknown provenance must remain distinguishable from confirmed add-in provenance.

5. **[P2] Raw automation IDs are lost.** `scripts/capture-ui.py:163` records only the baseline-filtered `idMso`; it never stores the original automation ID. Reproduce with a group containing one known control and one control whose nonempty automation ID is absent from the baseline. The second control survives, but its automation ID does not. This loses a required capture fact and makes later matching harder. Preserve the raw identifier separately from a verified `idMso`.

## integration: needs-attention

6. **[P1] Every supported non-Word launch fails process validation.** `scripts/capture-ui.py:423` passes Excel, PowerPoint, Visio and Project windows to `OwnProcess`, but `scripts/lib/office_com.py:66` accepts only executables ending in `WINWORD.EXE`. Reproduce with installed Excel and `--app excel --tab Home`: initialization rejects the Excel process and takes the cleanup path instead of capturing. The shared helper must validate the expected executable supplied by its caller.

7. **[P2] `--expand` silently omits supported drop-downs.** `scripts/capture-ui.py:579` excludes `comboBox`, including the captured Font and Font Size controls. At `:581`, a menu with a nonempty automation ID absent from the baseline also cannot be resolved: it has no `idMso`, and the fallback searches only for an empty automation ID. Reproduce with an expandable combo box, or an unknown-ID menu beside a known control. Neither is expanded, yet capture succeeds. ## Dispositions after round 1

All nine verified and fixed, each with a regression in `test_capture_ui.py` unless noted. (1) Ownership comes before any document: an instance that already holds documents is refused untouched (`test_an_instance_that_already_holds_documents_is_never_used_or_closed`; removing the check fails it), and `close()` closes only the documents the tool created and quits only when nothing else is open, otherwise it refuses and leaves the instance running (`test_only_the_tools_own_document_is_closed_and_a_shared_instance_is_left_running`). (2) `publish()` keeps each original as a hard link and installs the new file with one atomic rename, so the destination always holds old or new content even if the process is killed (`test_the_destination_never_goes_missing_during_a_replace`); the docstring states the remaining limit for two-file publishes. (3) A repeated label is told apart by its UI Automation id before any counter, and `merge()` matches by parent and `uiaId` first and never moves an annotation onto a different control (`test_annotations_follow_the_control_not_the_encounter_order`). (4) Content the baseline cannot vouch for is no longer called an add-in: it goes to `build/capture-ui/<app>-unverified.json` marked `baselineMissing`, and the run lists it (tests for the group and the tab cases). (5) The raw UI Automation id is kept as the new schema field `uiaId`. (6) `OwnProcess` takes the expected executable and compares the image's exact file name (`is_executable`, tested in `test_word_commands.py`). (7) Expansion uses each record's own element and its expand pattern; combo box lists (fonts, sizes) are deliberately not expanded and counted in the run output. (8) A failed `GetPixel` read (`CLR_INVALID`) is a theme problem, not white (removing the guard fails `test_each_value_is_checked`). (9) Each run reports the baseline's core tabs the window did not show (Word: TabAddIns, TabBackgroundRemoval, TabBlogInsert, TabBlogPost, TabBroadcastPresentation, TabConflicts, TabDeveloper, TabDrawInk, TabOutlining, TabPrintPreview, TabSyntex, which are hidden or contextual by default) and that File (Backstage) is captured by the app's Backstage section; tabs captured in the full run: Home, Insert, Design, Layout, References, Mailings, Review, View, Help. Live rerun of the checkpoint: exit 0, 55 records, `check-inventory.py` exit 0; this run recorded no bounds because the title bar sample did not read white with the operator now at the desk (the check failed closed, as intended). ## adversarial: needs-attention

1. **[P1] Cleanup can quit an instance containing unowned documents after an exception.** `scripts/capture-ui.py:498` initializes `others = 0`; if a created document’s `Close()` or the subsequent document-count read throws, the `finally` block at `:511` interprets that default as proof the instance is empty. Cleanup must leave the instance running when its remaining documents cannot be established.

2. **[P1] An empty application is still not proof of ownership.** `scripts/capture-ui.py:443` checks for a running single-instance app before dispatch, but `:448` only checks document count afterward. Reproduce by starting PowerPoint without a presentation between the process check and `Dispatch`. The returned operator instance passes the zero-document check, is manipulated, and is quit during cleanup. The round-one fix protects populated instances but leaves the ownership race open.

## consistency: needs-attention

3. **[P1] Merge preserves control identities without remapping their captured children.** `scripts/capture-ui.py:218` retains existing IDs after matching by `uiaId`, but `:223` appends new records with their original captured `parent` values. Reproduce with two same-label expandable controls, First and Second, then reverse their traversal order and capture a new menu item under Second. The fresh capture gives Second the unsuffixed ID previously assigned to First. Merge retains First under that ID and appends Second’s item beneath First.
